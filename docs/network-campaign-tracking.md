# Network campaign tracking

The existing authenticated sync cron reads one due LinkedIn campaign per tick, inside its durable global lease. Eligible tenant and workspace filters apply before oldest-first candidate selection, with a two-second database deadline. Successful reads are due every five minutes; bounded exponential retries respect `Retry-After`. It sends no outreach. Email and network counters remain separate.

The official HeyReach Postman collection at https://documenter.getpostman.com/view/23808049/2sA2xb5F75 was inspected on October 19, 2026. `GET /campaign/GetById?campaignId=...` gives `id`, `organizationUnitId`, `campaignAccountIds`, `creationTime`, `progressStats.totalUsers` and status. Every returned identity must match the reviewed workspace/campaign/sender scope. `POST /stats/GetOverallStatsByCampaign` receives nonempty `campaignIds` and `accountIds`, plus creation time through observation time. Its `overallStats` rows must match the sole campaign and not be deleted. No empty filter, workspace discovery, personal inbox expansion or provider write is used.

The four cumulative metrics map `connectionsSent`, `connectionsAccepted`, `messagesSent`, and `totalMessageReplies`. They do not combine ordinary messages with InMail, infer meetings, or invent a unique-person/reply-rate denominator. `messagesSent` means ordinary LinkedIn messages; `replies` means provider-reported ordinary-message replies. Empty reports preserve null, distinct from an explicit source zero. A fresh scoped read for the approved launch returned HTTP 200, 47 leads and an empty statistics array. Campaign metadata does not supply a schedule, so none is invented.

The new `client_outreach_network_campaigns` view exposes only neutral IDs, names, statuses, validated counts, timestamps and normalized schedules behind the existing tenant/feature authorization. Saving observations atomically checks campaign ownership, binding version, sender versions and active feature. Client roles cannot write statistics or inspect provider credentials.

Migration 0117 permits the same LinkedIn credential/workspace pair across tenants, while the durable credential guard rejects mismatched workspace identities. Exclusive sender IDs and global campaign assignment constraints remain unchanged. Existing configurations are neither migrated nor reassigned. Migration 0118 excludes provider mirror duplicates when any imported row already owns the email or profile identity, including escrow records. Original priority, identity and review decisions remain authoritative. Live campaign membership, status and activity overlay that canonical record. A bounced or opted-out email projects as unverified, so stale import verification cannot imply deliverability. Neither source records nor escrow decisions are mutated. Campaign-specific mirror details remain available separately.

Verification uses a new isolated `Covora_Ice_Live_20261019` stack on ports 60921/60922. Existing stacks and the legacy content portal are untouched. Database types are generated from that new schema, not manually edited. No production activation is part of this patch.
